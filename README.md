# ESP32_STP_PID_DISP — автоматический регулятор давления

Прошивка для микроконтроллера **ESP32**, которая **сама поддерживает заданное давление газа** в замкнутом объёме (порядка 100 мл). Вы говорите устройству «держи 500 кПа» — а оно само открывает и закрывает клапаны, чтобы давление вышло на эту цифру и оставалось на ней, даже если объём потихоньку травит.

По смыслу это как круиз-контроль в автомобиле, только вместо скорости автомобиля удерживается **давление**, а вместо педали газа — два управляемых клапана.

## 1. Что делает устройство простыми словами

Есть герметичный объём (баллон/камера), к которому подключены:

- **источник давления** (компрессор/линия высокого давления) — отсюда газ можно **набирать**;
- **атмосфера** — сюда газ можно **стравливать** (выпускать).

Между ними стоят два «крана», которыми рулит ESP32. Задача прошивки — крутить эти краны так, чтобы давление в объёме стало равно **уставке** (заданному числу) и держалось на ней.

Давление измеряется отдельным **датчиком давления** и показывается на маленьком **экране**. Команды («какое давление держать», «сбросить всё», «проверить утечку») можно подавать двумя способами: через **USB-кабель** с компьютера или по **WiFi** с телефона.

Единица измерения давления здесь — **кПа** (килопаскаль). Уставку можно задавать от 0 до 4000 кПа.

## 2. Из чего собрана система (железо)

```
                    ┌─────────────────────────────┐
                    │           ESP32             │  ← «мозг», на нём крутится прошивка
                    │  (плата TTGO с экраном)     │
                    └──┬───────┬───────┬───────┬──┘
                       │       │       │       │
        ┌──────────────┘       │       │       └──────────────┐
        │                      │       │                      │
        ▼                      ▼       ▼                      ▼
┌───────────────┐   ┌──────────────┐ ┌──────────────┐  ┌──────────────┐
│ Серво-кран    │   │ Шаговый      │ │ Датчик       │  │ Экран ST7789 │
│ (направление) │   │ двигатель    │ │ давления     │  │ (TTGO)       │
│               │   │ + игольчатый │ │ (по UART)    │  │ показывает   │
│ набор/сброс/  │   │ клапан       │ │ меряет кПа   │  │ цифры        │
│ нейтраль      │   │ (сила потока)│ │              │  │              │
└───────────────┘   └──────────────┘ └──────────────┘  └──────────────┘
```

Два исполнительных механизма работают в паре, и это **ключевая идея всего проекта**:

| Механизм | За что отвечает | Аналогия |
|---|---|---|
| **Серво-кран** (обычная RC-серва) | **Направление**: набирать давление, стравливать или «закрыто» (3 положения) | Поворот крана: «налив» / «слив» / «перекрыто» |
| **Игольчатый клапан** на **шаговом двигателе** (NEMA17) | **Сила потока**: насколько широко приоткрыта щель, через которую идёт газ | Насколько сильно открутили кран — тонкая струйка или мощный напор |

> Почему так? Потому что серво может надёжно выбрать одно из трёх направлений, но не умеет точно дозировать поток. А шаговый двигатель умеет очень точно (по «шагам») приоткрыть иглу на нужную величину, но не задаёт направление. Вместе они дают и направление, и точную дозировку. Поэтому **открытие иглы — всегда положительное число (в «шагах»), а знак (набирать или стравливать) задаёт серво**.

## 3. Распиновка — что куда подключено

Номера ножек (GPIO) заданы в файлах [`main/config.h`](main/config.h) и [`main/pressure_sensor.h`](main/pressure_sensor.h).

**Шаговый двигатель (игольчатый клапан):**

| Сигнал | GPIO | Назначение |
|---|---|---|
| `PIN_STEP` | 21 | импульс «сделай один шаг» |
| `PIN_DIR` | 17 | направление вращения (открыть / закрыть) |
| `PIN_ENABLE` | 32 | сброс ошибки драйвера |
| `PIN_ALARM` | 33 | вход «авария/упор» — по нему ищется механический ноль |

**Серво-кран:**

| Сигнал | GPIO | Назначение |
|---|---|---|
| `PIN_SERVO` | 2 | управляющий ШИМ-сигнал (50 Гц). 90° = нейтраль; крайние 0°/180° — набор и сброс |

**Датчик давления (отдельная микросхема, общается по UART):**

| Сигнал | GPIO | Параметры |
|---|---|---|
| `PIN_RX1` | 26 | приём данных от датчика |
| `PIN_TX1` | 27 | передача запросов датчику |
| — | — | скорость 19200, чётность odd, опрос каждые 50 мс |

**Экран ST7789 (подключён по шине SPI):**

| Сигнал | GPIO |
|---|---|
| MOSI / SCLK | 19 / 18 |
| CS / DC / RST | 5 / 16 / 23 |
| BL (подсветка) | 4 |

**Кнопка Boot (GPIO 0)** на плате используется как «обнулить датчик»: коротко нажал — датчику сообщается, что текущее давление считать нулём.

## 4. Как устроена программа в целом

Прошивка написана на языке **C** под фреймворк **ESP-IDF** (официальная среда разработки для ESP32). Внутри работает операционная система реального времени **FreeRTOS** — она позволяет нескольким кускам кода («задачам») выполняться как бы одновременно.

Программа разбита на несколько параллельных задач. Представьте их как нескольких работников, каждый занят своим делом:

```
┌──────────────────────────────────────────────────────────────────┐
│                        ESP32 (FreeRTOS)                            │
│                                                                    │
│  ┌────────────────────┐   меняет        ┌──────────────────────┐  │
│  │ Задача-РЕГУЛЯТОР    │◄─── уставку ────│ Приём команд по USB  │  │
│  │ pid_regulator_task │                  │ usb_uart_rx_task     │  │
│  │                    │                  └──────────────────────┘  │
│  │ КАЖДЫЕ ~20 мс:     │                  ┌──────────────────────┐  │
│  │ • читает давление  │◄─── уставку ─────│ Главный цикл app_main│  │
│  │ • решает, что      │                  │ забирает команды WiFi│  │
│  │   делать с краном  │                  └──────────┬───────────┘  │
│  │ • двигает иглу/    │                             │              │
│  │   серво            │                  ┌──────────▼───────────┐  │
│  └─────────┬──────────┘                  │ WiFi + TCP сервер    │  │
│            │ читает                       │ (точка доступа)      │  │
│            ▼                              └──────────────────────┘  │
│  ┌────────────────────┐   обновляет      ┌──────────────────────┐  │
│  │ Опрос датчика      │── pressure1_kPa─►│ Задача-ЭКРАН         │  │
│  │ (таймер, 50 мс)    │                  │ display_update_task  │  │
│  └────────────────────┘                  │ рисует цифры,        │  │
│                                          │ опрашивает кнопку    │  │
│                                          └──────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘
```

Задачи общаются между собой через несколько **общих переменных** (объявлены в [`config.h`](main/config.h)). Самые важные:

- `setpoint_kPa` — **уставка**: какое давление надо держать (это число меняют команды);
- `pressure1_kPa` — **текущее давление** с датчика (его обновляет опрос датчика, читают все остальные);
- `current_valve_position` — текущее положение иглы в «шагах».

> **Почему команды по WiFi исполняет главный цикл, а не сама WiFi-задача?** Чтобы два источника команд (USB и WiFi) не лезли в общие переменные одновременно и не мешали друг другу. WiFi-задача просто складывает команды в очередь, а разбирает их тот же код, что и USB-команды. Это убирает целый класс трудноуловимых ошибок («гонок»).

## 5. Что происходит при включении

Функция `app_main()` в файле [`main/main.c`](main/main.c) запускает всё по порядку:

1. **Печатает серийный номер** чипа в лог (берётся из «прошитого» на заводе MAC-адреса — он уникален для каждой ESP32).
2. **Инициализирует экран** (`LCD_init`).
3. **Поднимает приём команд по USB** и запускает задачу отрисовки экрана (`pressure_ui_and_usb_init`).
4. **Запускает опрос датчика давления** (`pressure_sensor_init`) — раз в 50 мс датчику уходит запрос, ответ раскодируется в `pressure1_kPa`.
5. **Калибрует механику** (`hardware_setup_and_calibrate`):
   - настраивает серво и ножки шагового двигателя;
   - **ищет механический ноль иглы** (хоминг): медленно закручивает иглу до упора, пока драйвер не подаст сигнал «авария/упор» на пин ALARM — эта точка считается нулём;
   - если в системе **осталось давление** выше 5 кПа — автоматически **продувает** объём (открывает иглу настежь, стравливает в атмосферу, возвращает иглу в ноль).
6. **Запускает задачу-регулятор** (`regulator_start_task`) — главный «мозг» управления.
7. **Поднимает WiFi и TCP-сервер** (`wifi_tcp_init`).
8. Дальше `app_main` крутится в вечном цикле и **разбирает команды, пришедшие по WiFi**.

После этого устройство готово к работе и ждёт команду `set X`.

## 6. Логика регулирования — самое главное

Весь «интеллект» живёт в файле [`main/pressure_regulator.c`](main/pressure_regulator.c), в задаче `pid_regulator_task`. Она просыпается примерно **каждые 20 мс**, смотрит на разницу между целью и реальным давлением и решает, что делать с краном и иглой.

Эту разницу называют **ошибкой**:

```
ошибка = уставка − текущее давление
```

- ошибка **большая и положительная** → давление сильно ниже цели → надо **набирать**;
- ошибка **большая и отрицательная** → давление выше цели → надо **стравливать**;
- ошибка **около нуля** → мы на цели → надо **держать**.

### 6.1 Каскад: «сначала какая нужна скорость, потом как её добиться»

Наивный подход «ошибка большая — открой клапан сильнее» работает плохо: газ у цели течёт иначе, чем вдалеке, и систему то «проскакивает», то она еле ползёт. Поэтому здесь сделано **двухуровневое (каскадное) управление**:

```
         ┌─────────────────────────────────────────────────────────┐
         │  ВНЕШНИЙ уровень: "насколько быстро менять давление?"    │
         │                                                         │
         │   ошибка ──► таблица ──► желаемая СКОРОСТЬ dP/dt         │
         │   далеко от цели → быстро (до 100 кПа/с)                 │
         │   близко к цели  → медленно (доли кПа/с)                 │
         └───────────────────────────┬─────────────────────────────┘
                                     │ желаемая скорость
                                     ▼
         ┌─────────────────────────────────────────────────────────┐
         │  ВНУТРЕННИЙ уровень (PI-регулятор по скорости):          │
         │  "как открыть иглу, чтобы РЕАЛЬНАЯ скорость = желаемой?" │
         │                                                         │
         │   сравнивает реальную dP/dt с желаемой ──► открытие иглы │
         └───────────────────────────┬─────────────────────────────┘
                                     │ открытие иглы (в шагах)
                                     ▼
                          серво задаёт направление,
                          шаговик выставляет открытие
```

- **Внешний уровень** — это «умная рампа подъезда». Чем дальше давление от цели, тем большую скорость изменения он заказывает. Совсем рядом с целью заказывается крошечная скорость — чтобы плавно подкрасться и не проскочить. (Реализовано таблицей в функции `desired_rate_from_error`.)
- **Внутренний уровень** — это **PI-регулятор**, который подбирает открытие иглы так, чтобы **реальная** скорость роста/падения давления совпала с заказанной. (Функция `rate_control_step`.)

> **Что такое PI-регулятор?** Это классический способ автоматически подгонять «ручку» (тут — открытие иглы) под нужный результат. **P** (пропорциональная часть) реагирует на текущую ошибку: больше промах — сильнее правка. **I** (интегральная часть) накапливает ошибку со временем и убирает маленький стабильный недобор. Подробнее — в [словаре терминов](#12-словарь-терминов).

Здесь есть тонкость: коэффициенты внутреннего PI **настроены один раз и не меняются**. Так можно, потому что связь «открытие иглы → расход → скорость» почти линейна по всему диапазону, а нелинейность (у цели газ течёт слабее) автоматически гасится самой обратной связью по скорости.

### 6.2 Почему у самой цели всё устроено иначе — «микродозы»

Когда давление подошло вплотную к цели, нужная скорость становится крошечной — вроде 0.01–0.02 кПа/с. Беда в том, что **датчик так точно скорость измерить не может**: его собственный шум (±0.5 кПа/с) больше полезного сигнала. Если в этот момент продолжать рулить «по скорости», регулятор начинает дёргаться: то наберёт лишнего, то стравит.

Поэтому у цели включается другая стратегия — **HOLD** (удержание):

1. В покое объём **запечатан**: игла прикрыта, серво в нейтрали — газ никуда не идёт.
2. Когда давление всё же уползло, регулятор делает короткий **эпизод-микродозу**: серво поворачивается в нужную сторону, игла приоткрывается на **фиксированную небольшую величину**.
3. Раз в **5 секунд** регулятор смотрит не на скорость, а на **сам факт**: сдвинулось ли давление к цели за это окно — и чуть подстраивает величину дозы (приоткрыть/прикрыть). За 5 секунд даже крошечное изменение видно сквозь шум.

### 6.3 Быстрый поиск «порога потока» (SEARCH)

У игольчатого клапана есть **мёртвый ход**: пока игла не приоткрылась до определённого порога, газ вообще не идёт. Ползти к этому порогу по чуть-чуть — это десятки секунд впустую. Поэтому перед дозированием регулятор делает **быстрый поиск порога** (`hold_search_step`): он шаг за шагом приоткрывает иглу и следит за давлением; как только давление впервые тронулось — порог найден, и дальше регулятор работает уже от него.

### 6.4 Точное удержание (FINE) — стоять без подкачек

Самый аккуратный режим. Идея: вместо того чтобы периодически «подкачивать» давление дозами, найти **такое открытие иглы, при котором приток газа ровно равен утечке** — и просто стоять на нём. Серво при этом постоянно держится в положении «набор», а игла стоит на найденном равновесном открытии.

Раз в 5 секунд регулятор смотрит, куда чуть сползло давление, и подвигает иглу на один шажок против сноса: давление росло — чуть прикрыть, падало — чуть приоткрыть. Когда за целое окно давление почти не шелохнулось — равновесие найдено и запомнено.

> Этот режим включается флагом `hold_fine_enable` и срабатывает только когда на цель вышли **набором** (а не сбросом) и доза уже проверена делом.

### 6.5 Защита от «битых» показаний датчика

Иногда датчик по линии связи присылает искажённое значение, которое формально проходит проверку. Один такой выброс может надолго «отравить» расчёты. Поэтому если мгновенная скорость давления превышает физически возможную (`> 400 кПа/с`), такой отсчёт **игнорируется** — но не более 10 подряд, чтобы не «залипнуть», если давление и правда резко поехало.

## 7. Режимы работы (автомат состояний)

Регулятор в каждый момент находится в одном из состояний. Переходы между ними и составляют его поведение:

```
            команда "set X"
   ┌──────┐ (новая уставка)  ┌──────────────────────────────────────┐
   │ IDLE │ ───────────────► │             RUNNING                  │
   │покой │                  │  (активное регулирование)            │
   └──┬───┘ ◄─── "idle"──────│                                      │
      │     (или цель достиг.)│  внутри по очереди работают фазы:    │
      │                       │   RATE  → подъезд по скорости        │
      │ "reset"               │   SEARCH→ поиск порога потока        │
      ▼                       │   HOLD  → удержание микродозами      │
   ┌────────┐                 │   FINE  → точное удержание           │
   │HOMING  │                 └──────────────────────────────────────┘
   │сброс   │
   │давления│                 ┌────────┐
   └────────┘                 │ LEAK   │ ◄─── команда "leak"
                              │ тест   │      (накачать, запечатать,
                              │ утечки │       измерить падение, стравить)
                              └────────┘
```

| Состояние | Что делает |
|---|---|
| **IDLE** (покой) | Ничего не регулирует. Серво в нейтрали, игла закрыта. Сюда же приходит по команде `idle`/`abort`. |
| **RUNNING** (работа) | Главный режим. Внутри сам переключает фазы **RATE → SEARCH → HOLD → FINE** (см. [раздел 6](#6-логика-регулирования--самое-главное)). |
| **HOMING** (сброс) | Физически стравливает всё давление: серво на сброс, игла настежь, ждёт падения, закрывает. Запускается командой `reset`. |
| **LEAK** (тест утечки) | Разовая проверка герметичности: накачивает объём, запечатывает, 5 секунд измеряет, насколько упало давление, печатает скорость утечки и стравливает всё. |

Внутри **RUNNING** фазы переключаются так: сначала **RATE** быстро подвозит давление к цели; у самой цели PID выключается и, если порог потока ещё неизвестен, включается **SEARCH**; затем держим цель в **HOLD** микродозами или, если условия позволяют, в точном **FINE**.

## 8. Команды управления

Команды можно слать **по USB** (скорость порта 115200) или **по WiFi** (см. следующий раздел). Текст команды — одна строка. Регистр букв не важен (`set`, `SET` — одно и то же). Разбором занимается функция `handle_command` в [`main/main.c`](main/main.c).

| Команда | Что делает |
|---|---|
| `set X` | Задать **уставку** = X кПа (например `set 500`). Это запускает регулирование. |
| `idle` / `abort` | Остановить регулирование: серво в нейтраль, игла закрыта. |
| `reset` | **Физически сбросить** всё давление в атмосферу (хоминг по давлению). |
| `home` | Заново **найти механический ноль** иглы (закрутить до упора). |
| `leak` | Запустить **тест утечки** (накачать → запечатать → измерить → стравить). |
| `zero` | **Обнулить датчик**: сообщить ему, что текущее давление = 0. ⚠️ Запускать только когда в системе реально атмосфера, иначе датчик собьётся. |
| `sn` | Показать **серийный номер** чипа. |
| `range [N]` | Прочитать **рабочий диапазон** датчика (без аргумента — текущий, `N`=0..4 — конкретный). |
| `setrange N` | **Выбрать** рабочий диапазон датчика (`N`=0..4). |
| `ser 1 A` | Вручную повернуть серво №1 на угол `A` (0..180°). Для тестов; в режиме RUNNING регулятор перебьёт это значение. |

В ответ на команду устройство шлёт короткое подтверждение и в USB-консоль, и всем подключённым по WiFi клиентам.

## 9. Управление по WiFi

Сетевая часть — в файлах [`main/wifi_tcp.cpp`](main/wifi_tcp.cpp) и [`main/wifi_tcp.h`](main/wifi_tcp.h). По умолчанию ESP32 поднимает **собственную точку доступа** (режим AP) — то есть раздаёт свой WiFi, к которому можно подключиться напрямую, без роутера:

| Параметр | Значение |
|---|---|
| Имя сети (SSID) | `ESP32_PID` |
| Пароль | `12345678` |
| IP-адрес устройства | `192.168.4.1` |
| TCP-порт для команд | `3333` |

**Как подключиться:**

1. На телефоне/компьютере подключитесь к WiFi-сети `ESP32_PID` (пароль `12345678`).
2. Любым TCP-клиентом (например приложением-терминалом) откройте соединение на `192.168.4.1`, порт `3333`.
3. Шлите те же команды, что и по USB, по одной в строку: `set 500`, `reset` и т.д.

Можно подключить до 3 клиентов одновременно. «Мёртвые» соединения сервер сам обнаруживает и закрывает примерно за 11 секунд (механизм TCP keepalive).

> При желании можно переключить ESP32 в режим **STA** (когда она сама подключается к существующему роутеру или к другой ESP32) — для этого в [`wifi_tcp.h`](main/wifi_tcp.h) меняется `WIFI_TCP_MODE_AP` на `0` и прописывается имя/пароль чужой сети.

## 11. Как собрать и прошить

Проект собирается стандартными средствами **ESP-IDF** (целевой чип — ESP32). После установки ESP-IDF и активации его окружения команды такие:

```bash
# выбрать целевой чип (один раз)
idf.py set-target esp32

# собрать прошивку
idf.py build

# прошить плату и открыть монитор логов
#   замените COMx на ваш COM-порт (в Linux/Mac — /dev/ttyUSB0 и т.п.)
idf.py -p COMx flash monitor
```

В мониторе будут видны логи всех подсистем (`PID`, `SENSOR`, `HOMING`, `WIFI_TCP` и др.) — по ним удобно следить, в какой фазе сейчас регулятор и что происходит с давлением. Выход из монитора — `Ctrl+]`.

> Шрифты для экрана зашиваются автоматически: при сборке из папки `fonts/` собирается образ раздела `storage1` (см. строку `spiffs_create_partition_image` в [`CMakeLists.txt`](CMakeLists.txt)).

## 12. Словарь терминов

- **Уставка (setpoint)** — целевое значение, к которому стремится регулятор (здесь — желаемое давление в кПа).
- **Ошибка (error)** — разница между уставкой и реальным значением: `уставка − давление`.
- **кПа (килопаскаль)** — единица измерения давления. Для примера: атмосферное давление ≈ 101 кПа.
- **dP/dt (скорость давления)** — насколько быстро меняется давление, кПа в секунду.
- **PID / PI-регулятор** — автоматический алгоритм управления. Подгоняет «ручку» так, чтобы свести ошибку к нулю. Состоит из трёх частей:
  - **P (пропорциональная)** — правка тем сильнее, чем больше текущая ошибка;
  - **I (интегральная)** — накапливает ошибку во времени и убирает маленький, но стабильный недобор;
  - **D (дифференциальная)** — реагирует на скорость изменения ошибки (в этом проекте практически не используется — отсюда «PI», а не полный «PID»).
- **Каскадное управление** — два вложенных регулятора: внешний задаёт цель (нужную скорость), внутренний её достигает (рулит иглой).
- **Шаг (step)** — минимальное перемещение шагового двигателя. Открытие иглы измеряется в шагах: больше шагов — шире щель — сильнее поток.
- **Хоминг (homing)** — поиск опорной «нулевой» точки механики. Игла закручивается до упора, и эта точка принимается за ноль отсчёта.
- **Мёртвый ход / порог потока (cracking point)** — открытие иглы, ниже которого газ ещё не течёт вообще.
- **EMA (экспоненциальное скользящее среднее)** — способ сглаживания шумных измерений: новое значение — это смесь «в основном прошлого сглаженного и чуть-чуть свежего». Так гасятся одиночные выбросы датчика.
- **UART** — простой проводной протокол последовательной связи «по двум проводам». По нему ESP32 общается и с датчиком давления, и с компьютером по USB.
- **TCP / порт** — способ передачи команд по сети. «Порт» — это номер «двери», через которую клиент стучится к серверу (здесь — 3333).
- **AP / STA** — два режима WiFi. **AP** (точка доступа) — ESP32 сама раздаёт сеть. **STA** (станция) — ESP32 подключается к чужой сети.
- **FreeRTOS** — операционная система реального времени, которая позволяет нескольким «задачам» выполняться параллельно на одном чипе.
- **GPIO** — программно управляемая ножка микроконтроллера (вход или выход).
- **ШИМ (PWM)** — способ «дозировать» сигнал быстрым включением-выключением. Им задаётся угол поворота серво.
